# M2: DNS-BERT + Isolation Forest baseline

Owner: Thierry · Backup: Yehan · Trello: "[Thierry] M2: DNS-BERT tokenizers + pre-training + Isolation Forest on CIC"

## What it does
- **DNS-BERT** (`models/m2_dnsbert.py`): BERT, 4 layers, hidden 256, 4 heads, max 64 tokens, MLM pre-training
  on **benign names only** (CIC benign + Tranco top sites). Score = pseudo-log-perplexity (mean masked-token NLL);
  higher = more suspicious. Scoring is batched: every masked copy of a query, and copies from many queries,
  go through one forward pass, and only masked positions hit the MLM head. Unique qnames are scored once.
- Also outputs `info_bits` per query, I(q) = -sum log2 P(t_i | rest) (proposal eq. 1), for leakage accumulation.
- **Tokenizers:** BPE (8k vocab, main) and character-level (ablation 1); both trained on benign names only.
  Case is kept (tunnel encodings are often mixed-case; benign names are lowercase).
- **Isolation Forest** (`models/iforest_baseline.py`): benign-only, on the **M1 feature set**
  (`models/m1_features.py`: per-query + per-host window features), with M1's CIC leakage guard. On CIC that leaves
  11 features: entropy, n_digits, n_upper, n_special, digit_ratio, resp_size, qlen_wire, h_qpm, h_uniq_ratio,
  h_ent_mean, h_ent_std. Pass `feature_cols` to use the parser's feature table once it exists.
- **Threshold** (written to the results JSON as `threshold`): the latest 10% of benign training rows by time are held
  out and never trained on; the threshold is their 99th-percentile score (<= 1% FPR), so the eval module never picks
  it on the test set. Known limitation, fixed in Phase 2: on CIC these rows come almost entirely from one capture
  (`benign_heavy_3.pcap`), because "latest by time" is taken across the whole table, not per capture.

Both follow the contract interface: `train(train_df, cfg)`, `score(model, df)`, `save`, `load`.

## Run
```bash
pip install -r requirements-m2.txt
python scripts/cic_to_queries.py --raw data/raw/cic --out data/processed/cic/queries.parquet
python contracts.py data/processed/cic/queries.parquet
python -m models.m2_run --model m2 --exp E2 --data data/processed/cic/queries.parquet \
    --tranco data/external/tranco.csv --ckpt-dir <shared drive>/ckpt_bpe_v2
python -m models.m2_run --model m2 --exp E2 --tokenizer char --tag ablation1_char --data ...
python -m models.m2_run --model iforest --exp E2 --data data/processed/cic/queries.parquet
python -m pytest tests/test_m2.py -q
```
Output: `results/<model>/<exp>[_<tag>].json` in the contract format (`docs/contracts.md` section 3): scores,
labels, tools, src_hosts, session_ids, ts, threshold, info_bits (M2), train time, per-query latency (batch of 1),
config. Splits: the table's `split` column if present, else time-based 70/30 on `ts`.
On Colab: `notebooks/m2_dnsbert_colab.ipynb` (set `RAW_DIR` and the shared folder `SHARED` in the first cell;
checkpoints go to `SHARED/ckpt_*_v2` and resume after a disconnect).

Synthetic test data (`scripts/make_synthetic_sample.py`) is for code testing only, never for reported results.

## CIC-Bell-DNS-EXF-2021: what the raw data really looks like (read before using it)
Built with `python scripts/cic_to_queries.py --raw data/raw/cic` (stopgap until the parser card lands).
Download the **PCAP** folder from the CIC site (registration needed); the CSVs have no query text.

- **snaplen = 96 bytes.** Every packet is cut at 96 bytes, so only ~40 characters of each query name survive.
  Benign names (median 14 chars) are intact; ~99.9% of exfiltration names are truncated and lose their
  attacker domain. `qname_truncated` flags this; `qlen_wire` keeps the true query size.
  -> On CIC, `len(qname)` is capped and is NOT the real query length.
- **qtype is lost for truncated queries** (it sits after the name; the table stores `UNKNOWN`). Using qtype on
  CIC leaks the label, and so do capped lengths and the lost domain; the IF baseline drops all of these via
  M1's leakage guard (`models/m1_features.py`).
- **Only one attack tool** (DNSExfiltrator, base64url chunks `<n>.<data>` after an `init.<base32>` query),
  from one host. Attack pcaps also hold ~0.3% normal Windows lookups; those are labelled benign.
- **Benign traffic is scripted top-site lookups** (`domains_*.txt`), so it overlaps heavily with Tranco.
  CIC is an easy benchmark (IF baseline already reaches ROC-AUC 1.0); generalisation must be shown on the
  testbed, E3 and E5.
- Split: per capture file, first 70% of queries by time = train, rest = test.

## Phase 1 results: E2 on CIC (RTX 4060)
From `python -m eval.summarise`; all three use the validation threshold above.

| Model | F1 | FPR | ROC-AUC | Train time | Latency (batch of 1) |
|---|---|---|---|---|---|
| M2 DNS-BERT, BPE (`results/m2/E2.json`) | 0.9980 | 0.81% | 0.99998 | 71 s | 5.2 ms |
| M2 DNS-BERT, char, ablation 1 (`results/m2/E2_ablation1_char.json`) | 0.9979 | 0.83% | 1.00000 | 85 s | 6.3 ms |
| Isolation Forest (`results/iforest/E2.json`) | 0.9980 | 0.79% | 1.00000 | 0.7 s | 20.1 ms* |

- Trained on 246,202 unique benign names (CIC benign train split minus the held-out 10%, + Tranco top 200k);
  test = 113,078 queries. The selection rule picks M2 (BPE).
- Mean `info_bits`: benign ~37 bits, exfil ~465 (BPE) / ~315 (char) bits per query, even with exfil names
  truncated to ~40 chars by the CIC snaplen.
- As expected, CIC (one tool, unthrottled) is near-trivially separable; the informative comparisons are E3-E5.
- Latency was measured on an RTX 4060 (earlier T4 runs: 7.4 / 6.8 ms). The official latency table is re-run on
  one fixed machine for every model.
- \* The IF latency **excludes feature extraction**: the M1 features are computed once for the whole table before
  scoring (needed for the past-only host windows), so the 20 ms is sklearn overhead per call. A live detector
  would also pay the per-query feature cost.
